Hull , release process (CLI)
============================

Decision: builds are LOCAL and releases are uploaded BY HAND. The GitHub
Actions CI/release workflows were intentionally dropped (commit 64c0655); we do
not maintain a CI pipeline. Each platform has a one-command build that produces
the CLI + daemon binaries, and the AUR package builds from the tagged tarball.

Per-release checklist
---------------------

1. Tag the release:
     git tag v0.1.0 && git push --tags

2. Windows (on a Windows box):
     powershell -ExecutionPolicy Bypass -File build.ps1
     -> bin\hull.exe + bin\hulld.exe

3. Linux / macOS (needs go):
     ./build.sh
     -> bin/hull + bin/hulld
   Or install straight into ~/.local/bin with dependency checks and PATH wiring:
     ./install.sh          (or `yay -S hull` on Arch)

4. Create the GitHub Release for the tag and upload the binaries, naming the
   platform assets so users can grab them directly:
     - hull-windows-x86_64.zip      (bin\hull.exe + bin\hulld.exe)
     - hull-linux-x86_64.tar.gz     (bin/hull + bin/hulld)
     - hull-linux-aarch64.tar.gz    (Linux arm64, if built)
   The README's install instructions point at get.sh and ./install.sh.

5. AUR (Arch):
     cd packaging/aur
     # bump pkgver to match the tag, then:
     updpkgsums                    # pin the source checksum (replaces SKIP)
     makepkg --printsrcinfo > .SRCINFO
     # commit PKGBUILD + .SRCINFO to the AUR repo for `hull`

Notes
-----
- No code signing yet (Windows Authenticode / Apple Developer ID) , binaries
  are unsigned; users may see an OS warning on first run.
- This branch ships the CLI + daemon only. The desktop GUI lives on its own
  branch and is released separately.
