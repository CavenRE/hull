Hull release process
====================

.github/workflows/release.yml builds, signs and publishes a release when a v*
tag is pushed. .github/workflows/ci.yml runs go vet, the build, the race tests
and golangci-lint on Linux, Windows and macOS for each push to master and each
pull request.

One-time setup: the signing key
-------------------------------

`hull update` installs a download only when SHA256SUMS has a valid ed25519
signature, so each release must be signed.

1. Run: go run ./tools/sign genkey
2. Paste the public key into ReleaseKey in internal/version/release_key.go,
   and commit it.
3. Add the private seed as the repository secret HULL_SIGNING_KEY (Settings >
   Secrets and variables > Actions).

Until both are in place, the sign job fails and the workflow publishes
nothing.

Per-release checklist
---------------------

1. Add the notes to CHANGELOG.md under "## [X.Y.Z]" and commit. The workflow
   copies that section into the release notes.

2. Tag and push:
     git tag vX.Y.Z && git push --tags

3. The workflow builds the binaries, writes SHA256SUMS (its first line names
   the tag), signs it, and uploads these to the GitHub Release for the tag:
     - hull-windows-x64.exe
     - hull-linux-x64
     - hull-macos-intel
     - hull-macos-apple-silicon
     - SHA256SUMS and SHA256SUMS.sig
   The Windows binary gets its version resource from cmd/hull/versioninfo.json,
   stamped with the tag's version.

4. AUR (Arch):
     cd packaging/aur
     # set pkgver to the tag, then:
     updpkgsums                    # pin the source checksum
     makepkg --printsrcinfo > .SRCINFO
     # commit PKGBUILD + .SRCINFO to the AUR repo for `hull`

Local builds
------------

- Windows: powershell -ExecutionPolicy Bypass -File build.ps1   (bin\hull.exe)
- Linux / macOS: ./build.sh   (bin/hull)
  Or install into ~/.local/bin with dependency checks and PATH set-up:
    ./install.sh          (or `yay -S hull` on Arch)

If you change cmd/hull/versioninfo.json or cmd/hull/hull.ico, run
`go generate ./cmd/hull` and commit the new resource_windows_amd64.syso. CI
fails when the committed file does not match its sources.

Notes
-----
- The binaries have no OS code signature (Windows Authenticode, Apple
  Developer ID), so users may see an OS warning on first run. The ed25519
  signature protects `hull update` and nothing else.
- This branch ships the single hull binary only (the CLI and the daemon). The
  desktop GUI is released separately.
